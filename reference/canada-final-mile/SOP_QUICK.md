# 加拿大尾程派送报价执行卡 v2.0

本文件是实时报价入口。正常报价只读：

1. `SOP_QUICK.md`
2. `RULES.yaml`
3. `QUOTE_TEMPLATE.md`

仅在邮编缺失、split-record、BC旧数据、农村/湖边住宅等异常场景命中时，再读 `EDGE_CASES.md`。旧版长文档只做历史归档，不作为实时报价入口。

## 0. 硬阻断

- 地址类型未确认：停止报价，先确认商业/住宅/农村住宅。
- Google Maps 或明确证据冲突：停止报价，要求人工确认。
- 无可靠 Zone 或无可靠锚点：输出“转单/需供应商确认”，不要猜价。
- 三个查表文件缺失：停止报价，提示补齐文件。
- 基础价必须来自价格表，禁止按每托、里程、历史基准价自行计算。

## 1. 收集输入

必填信息：

- 完整地址、邮编、城市、省份
- 体积 CBM、毛重 KG、件数
- 包装类型：纸箱、木箱、托盘、编织袋/柔性包装等
- 单件尺寸，尤其是最长边是否大于 120cm
- 客户已给托数时，记录为显式托数
- 地址类型证据：商业、住宅、农村住宅，或未知

## 2. 确认地址类型

优先使用 Google Maps 或客户提供的明确证据。

- 商业地址：公司、仓库、工业园、办公室、商铺、商业街、商场、带明确企业名称的地点。
- 住宅地址：独栋、联排、公寓、住宅社区、无商业地点名称的住址。
- 农村/农场/湖边度假关键词命中：按住宅处理，见 `EDGE_CASES.md`。
- 未确认或证据矛盾：停止报价。

费用规则：住宅/私人地址加 `50USD/票`，商业地址不加住宅费。

## 3. 判断计费模式

- 编织袋/柔性包装 + 件数 >= 50 + 可堆叠：走包干价模式，约 `$580 USD/柜`，不按托数报价。
- 纸箱、木箱、托盘化货物、包装未知：按托数报价。
- 木箱：每件至少按 1 托；超长木箱每件按 2 托。

## 4. 计算计费托数

使用 `RULES.yaml` 的参数：

```text
体积托数 = ceil(CBM / 2)
重量托数 = ceil(KG / 500)
超长托数 = 件数 * 2，条件：任一单件长度 > 120cm
木箱托数 = 件数；若超长，则 件数 * 2
显式托数 = 客户已给托数，没有则忽略

计费托数 = max(体积托数, 重量托数, 超长托数, 木箱托数, 显式托数)
```

## 5. 查邮编与 Zone

查表顺序：

1. 用完整邮编查 `canadapostalcodeslist(1).json`，确认 preferred city。
2. 用邮编前三位 FSA 查 `Zone 邮编前缀 城市 省份 始发仓 查询表.json`。
3. 城市、省份一致时，采用该 Zone。
4. FSA 缺失时，用同城市+同省份锚点回退。
5. split-record 或双索引冲突时，查 `EDGE_CASES.md`；仍不确定则转供应商确认。

禁止规则：不要用 Zone 线性 `+1/+2/+3` 外推。

## 6. 按省份确定始发仓

省份规则覆盖 Zone 表里的旧 `origin` 字段：

- Calgary：BC、AB、SK、MB
- Toronto：ON、QC、NB、NS、PE、NL

BC 全境统一按 Calgary。BC 旧表显示 Toronto 时，按 stale origin 处理并覆盖为 Calgary。

## 7. 查基础价

用 `Zone 票价表（查表价格）.json` 查：

```text
origin + zone + billing_pallets = base_price
```

基础价必须来自表。表内无价、外推未确认、锚点不可靠时，转供应商确认。

## 8. 计算总价

```text
subtotal = base_price * 1.35
residential_fee = 住宅/私人地址 ? 50 : 0
quote_total = subtotal + residential_fee
```

尾板、手叉车、预约、等待费默认写入服务条款；只有客户明确需要或规则明确要求时才计入报价总价。

## 9. 输出报价

- 默认使用 `QUOTE_TEMPLATE.md` 的正式模板。
- 只有用户明确要“企微/群里短回复/短格式”时，使用企微短模板。
- 正式报价可保留 Zone；企微短格式不要输出 Zone、托数、回退细节。

## 10. 报价后自检

发送前逐项确认：

- 地址类型是否已确认，未知是否已阻断？
- 住宅/私人地址是否加了 `50USD/票`？
- 包装是否识别了编织袋、木箱、托盘、超长件？
- 计费托数是否取了 `max()`？
- BC 是否强制 Calgary？
- 基础价是否来自价格表？
- 总价是否为 `base * 1.35 + 已确认附加费`？
- FSA 缺失或 split-record 是否查了 `EDGE_CASES.md`？
- 是否用了正确模板？

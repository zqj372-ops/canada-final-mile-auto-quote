## Step-by-step Procedure

### 步骤1：解析货物信息
```
输入：件数/体积/重量/单件尺寸/包装类型
```

### 步骤2：计算计费托数
```
体积托数 = ⌈体积 ÷ 2⌉
重量托数 = ⌈总毛重 ÷ 500⌉
超长件（长度>120cm）：每件按2托
计费托数 = max(体积托数, 重量托数, 超长件托数)
```

### 步骤2.5：包装类型判断（v1.6新增）

报价前必须先识别包装类型，决定计费模式：

| 包装类型 | 计费模式 | 适用托数规则 |
|---------|---------|-------------|
| 纸箱/木箱 | 按托数计费 | 超长件×2、体积/重量取大值 |
| **编织袋/柔性包装** | **包干价模式** | 不按托数计费，报约$580 USD/柜包干价 |
| 托盘化货物 | 按托数计费 | 整托计算 |

**包干价触发条件**（同时满足）：
1. 件数 ≥ 50件
2. 包装 = 编织袋/柔性包装
3. 属可堆叠货物

**历史补全记录**：

|------|------|------|------|
| 2026-06-04 | 76件编织袋 L5S Mississauga | $5,569（按152托） | $580（包干价） |

#### 3.4 三级匹配回退（v1.5新增，v1.7修正）

当邮编前缀在Zone表中**查不到精确匹配**时，启动三级回退：

| 优先级 | 匹配方式 | 规则 |
|--------|---------|------|
| L1 | 邮编前缀+城市精确匹配 | 优先使用 |
| L2 | 邮编前缀同区段+同省份其他城市 | 选取同区段最近邻邮编 |
| L3 | Tavily验证取最近邻已知Zone城市 | 不允许线性+1/+2/+3 |

**⚠️ L3 关键修正（v1.7）**：
- L3 不能用线性归类（500km天差地别，误差极大）
- L3 必须 Tavily 搜索"该城市与邮编分区表内同省/邻近区段已知Zone城市"的实际距离
- 取**最近邻**已知Zone城市作为锚点
- 距离偏差只允许 ±50km
- 超范围（>200km无邻近锚点）→ 转单

**反面案例**：Abbotsford 距Calgary 903km，旧L3规则会得Zone4，实际V2S同省BC=Zone5
- Tavily查V2S距Abbotsford仅~10km → 采用V2S锚点=Zone5

#### 3.5 判断逻辑透明化（v1.5新增）

凡是触发 L2/L3 回退，**报价时必须输出判断逻辑摘要**，让用户可审核：

## 步骤7.5：查表价格自检规则（v1.10新增）

**触发场景**：报价后基础价查表后立即执行自检

**自检逻辑**：
```
1. 查表得到基础价 base
2. 立即计算 total = base × 1.35
3. 与相邻托数价格对比（±1托）
4. 偏差 > 20% → 强制复检
5. 偏差 > 50% → 必须人工复核
```

**反面案例**（2026-06-04 16:30）：
- J7H Zone7 12托 首次查表 = $920（错误）
- 实际 Zone7 11托=$1000, 12托=$1000, 13托=$1050
- 12托应 = $1000，偏差 = 8%（边界值）
- **正确价格**：$1000 × 1.35 = **$1,350**
- 错误价格：$920 × 1.35 = $1,242（少报 $108）

**避免措施**：
- 查表后必须**对照相邻行**（n-1, n, n+1）
- Zone7 边界值（10-12托）必须显式确认
- 自检时效：报价后 30 秒内必须完成

## v2.27 cache.py 兜底机制（v1.19 新增，2026-06-05 11:30）

### 触发背景

2026-06-05 启用 L5M 2R7 MISSISSAUGA 报价时，发现邮编分区表 `by_postal_prefix` **L5M 前缀完全缺失**。原 cache.py 直接返回 `Zone 0 MISS` 触发转单，**导致 L5M 类地址数据缺失时被误转单**。

### v2.27 升级内容

| 升级项 | 触发条件 | 行为 |
|--------|---------|------|
| **L1 前缀回退** | 精确 6 位邮编未命中 | 同前缀 3 位回退（同前缀同城市时可用）|
| **L1.5 Tavily 兜底** | L1 命中但 L2 缺数据 | 自动 Tavily 二次查询 |
| **L2.5 置信度标记** | Tavily 返回结果 | low/medium/high 标记，便于审查 |
| **7天兜底缓存** | 兜底结果 | 7天TTL（邮编数据稳定）|

### 调用链

```
get_postal_city(postal)
   ↓
   精确 6 位匹配 → 命中
   ↓ 失败
   前缀 3 位回退（单城市时）
   ↓ 仍失败
   返回 None
   ↓
get_zone(postal, city)
   ↓
   L1 精确匹配（邮编+城市）
   ↓ 失败
   L2 前缀匹配
   ↓ 失败
   L1.5 Tavily 兜底（仅当 L1 城市有值）
   ↓ 失败
   返回 Zone 0 MISS
```

### 兜底匹配级别返回值

| 返回值 | 含义 | 处理 |
|--------|------|------|
| `L1` | 邮编+城市精确命中 | 直接报价 |
| `L2` | 邮编前缀命中（忽略城市）| 需人工确认城市 |
| `L1.5-cached` | Tavily 兜底缓存命中（高置信度）| 可直接报价 |
| `L1.5-tavily` | Tavily 兜底返回低置信度 | **必须人工确认 Zone 归属** |
| `L1.5-low-confidence` | 兜底缓存低置信度 | 同上 |
| `MISS` | 完全无数据 | 转单 |

### 5条铁律（2026-06-05 11:25 11:30 立）

**铁律1**：任何报价必须先 `cache.get_price(zone, origin, pallets)` 取得 base + fuel，禁止凭经验
**铁律2**：纸箱/木箱包装必须严格按 SOP 公式 `max(⌈体积/2⌉, ⌈重量/500⌉, 超长件×2)`，禁止按"件数估算"
**铁律3**：始发仓判定必须根据 L1 城市所属省份（ON→多伦多，AB/SK/MB→卡尔加里），禁止人工指定
**铁律4**：当 L2 报 MISS 但 L1 命中时，强制走 v2.27 L1.5 兜底 + Tavily 二次
**铁律5**：报价输出前必须 echo `cache.get_price()` 完整结果（base/fuel/total），便于审计
